# ebook-factory：知识付费电子书批量生产器（电子书工厂）

把"一句主题 / 一段卖点文案 / 几个关键词"变成"排版精美、可直接上架的 PDF 电子书"，并自动套用统一的"××开窍"系列视觉。命令式：你给主题，我按检查表产出一整套。

## 何时使用

- 用户要出一本电子书/指南/秘籍/宝典，给的是主题、卖点文案或关键词，而非现成全文
- 用户想把零散知识点组织成结构化长稿（2-10 万字）并交付 PDF
- 用户要重排已有稿件成精装 PDF / 要统一成"开窍系列"视觉
- 用户要把这套制作流程本身固化成可复用工作流

不适用：单篇文章、非书籍类文档、纯翻译、营销短文。

## 系列化三要素（新建书前先想一遍）

**① 是否属"××开窍"系列？** 若是 → 读 `references/series_visual_guide.md`，封面/版式沿用开窍金 `#c9a227`，脚本里加 `series_label`（如"开窍系列 · 第一册"）；若否 → 可按主题选强调色（表见该文件）。

**② 章节骨架怎么搭？** 读 `references/outline_generator.md`（含三本已验证结构规律 + 任意主题→章节骨架的四步法 + 常见主题章名提案），按它把主题拆成 OUTLINE。

**③ 内容红线守死**（通用，见 writing_guide）：正向、合法、不教阴损/违法；涉"权谋/博弈/反击/控局"讲体面自保、正向竞争、长期共赢；涉"骗局/割韭菜/风险"教识别与自保，不教操控诈骗。

## 流水线（按序执行）

### 1. 澄清需求（模糊输入必须先问）

先问四个维度，避免白写几万字：
- **书名/定位**：主题词 + 一句话定位（帮读者解决什么问题）
- **交付形态**：(a) 完整书稿 + PDF（推荐）(b) 先出大纲目录 (c) 只做营销文案
- **篇幅**：精炼版 3-4 万 / 标准版 6-8 万 / 深度版 10 万+ 字
- **风格**：口语化实战（推荐）/ 系统化教程 / 混合

若用户只给了几个关键词（像三次做书那样），可进一步让他在"预置主题池"里选一个，或直接按其关键词拆主线。把推荐项放第一位并标"（推荐）"。

### 2. 搭项目目录 + 写写作规范

建项目目录（如 `D:\项目\截图工具\<书名>\`，含 `chapters/`、`assets/`），把 `references/writing_guide.md` 复制为 `WRITING_GUIDE.md`（可直接复用），把 `scripts/build_book.py` 复制过去。写作规范核心：口语化、先结论、称"你"、禁官腔词、不用 emoji、每节落到"能用"、红线正向。

### 3. 写全书大纲 `OUTLINE.md`（用 outline_generator）

拆出 序言 + N 章 + 结语。每章 6-7 个小节，**每节给一句"认知翻转"式核心结论**（这是多 Agent 产出不跑偏的关键）。在 OUTLINE 末尾附一段"内容红线"。若复用已有主题（社交/搞钱/识人），直接取对应存量骨架微调即可。

### 4. 自己写序言 + 结语（定调子）

这两个必须自己写，确立全书口吻与价值观基准，作为后续 Agent 的文风样板。四段式序言 / 三段式结语结构见 `series_visual_guide.md` 第四节。写完先读一遍，**确认结语没有再重复第十章结尾的关键比喻**（第三次做书踩过：结语"棋局"与第十章末段重复，需改）。

### 5. 派 2-4 个并行 Agent 写正文（每台 2-4 章）

给每个 Agent 的 prompt 必须自包含，让它"先读规范+序言样板+大纲，再围绕负责每节的**核心结论**写，结尾交小节数与字数报告"：
1. 角色与项目背景（知识付费电子书、作者署名、口语化实战）
2. **必须读取**：`WRITING_GUIDE.md` + `chapters/00_preface.md` + `OUTLINE.md`
3. 它负责的章节文件清单 + 每节核心结论
4. 每章格式：`# 第X章 篇名` → 150-250 字章引言 → `## 小节标题` → 每节 850-950 字按 6 段模板 → 每节 ≥1 个引号话术模板
5. 质量要求 + 红线（同步骤 2）
6. 输出：每章一个 UTF-8 md，命名 `0X_篇名.md`

**Agent 失败兜底（重要）**：若某组 Agent 因限流（429）/ 其它原因失败，**不要等重置、不要阻塞交付**——按同一份规范与大纲**自己直接写**剩余章节（每章一个 Write 调用），保证文风一致。完成后照常走质检。

**网络型失败（502 / Stream timeout / DNS 解析失败）**：这类失败与 429 不同，重试同一批 Agent 大概率还会挂（实测连续两轮、4 台全挂，白耗 6 小时）。
处置顺序：① 先 `ls chapters/` 看实际落盘到哪一章；② 用 **SendMessage 续跑**而不是重新 spawn（续跑时把"文件清单 + 文风样板 + 模板段必须以「（英文为 “）开头 + 禁用词 + 大纲路径"重述一遍，实测续跑能多落几章）；③ 续跑再挂就**停止派 Agent，主 Agent 直写收口**。不要在这条通道上来回试。

### 6. 质检（合并前必做）

- `Grep` 查禁用词：`首先|其次|综上所述|总而言之|不难发现|众所周知|相信通过|一方面|另一方面|值得注意的是|在这个时代`，命中即修
- Python 统计各章字符数，核对达标；总字数若明显低于篇幅档位，派一个 Agent 对偏薄的章"增厚 80-130 字/节"，不许改动已有标题与话术模板
- 抽读首末两章验证文风、话术模板到位
- 统计每章 `「` 数，确保与小节数一一对应（每节至少 1 个）

### 7. 生成 PDF

改复制到项目目录的 `build_book.py` 顶部 `CONFIG`（书名/作者/章节目录/output_name；系列册可加 `series_label`、`accent`），运行 `python build_book.py`。脚本做三件事：读 chapters/*.md → 转精美 HTML（系列封面卡片 + 目录 + 章节样式，引号话术自动加模板框）→ 调 Edge headless `--print-to-pdf` 出 PDF。

### 8. 视觉验证

Edge headless `--screenshot` 截封面 + 第一章正文图，肉眼确认排版。若封面在 PDF 白边被裁，改用"白底 + 深色卡片"结构（**切勿用负 margin 抵消 @page 边距，打印会被裁剪**）。

### 9. 交付

`present_files`：PDF（主交付）+ HTML 原稿（artifact card）。章节 md 与构建脚本保留在项目目录，便于改稿重出。

## 关键命令（本机 Windows）

```bash
# 出 PDF（build_book.py 已配好 CONFIG 后，在项目目录）
python build_book.py
# 命令行快速覆盖（不改 CONFIG）
python build_book.py --chapters ./chapters --out 书名 --series "开窍系列 · 第二册" --accent "#c9a227"

# 视觉复核封面/正文
"C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" --headless --disable-gpu \
  --user-data-dir="<项目>/assets/edge_tmp" --window-size=1080,1700 \
  --screenshot="<项目>/assets/cover.png" --virtual-time-budget=15000 \
  "file:///<项目>/<书名>.html"
```

Edge 中文路径用正斜杠 `file:///D:/xxx/book.html`；`--user-data-dir` 给项目内独立临时目录，避免与运行中的 Edge 冲突。

## 技术坑位清单（三本书踩过，务必规避）

1. **Python 脚本内避免中文字面量**（打包/校验脚本常按 GBK 读文件）：脚本里检测"「"要用 `\u300c` 转义，或给目标文件里含非 GBK 字符的字段用 ascii 转义；Windows 下可用 `PYTHONUTF8=1 PYTHONIOENCODING=utf-8` 兜底。
2. **封面白边**：不用 `margin: -20mm -18mm` 抵消 `@page` 边距，打印会被裁。用"白底+深色卡片"（当前 build_book.py 即是标准写法）。
3. **结语与大章结尾比喻重复**：第 4 步写完序言结语后自查，改掉与最后一章重复的关键句。
4. **Agent 限流（429）**：见流水线第 5 步，自己直接写兜底，不阻塞。
5. **Edge 截图**：必须用 `--headless=new`（老的 `--headless` 在本机静默失败、不产出文件）；输出路径用 `D:\...` 反斜杠形式，POSIX 的 `/tmp/...` 写不出来；`--user-data-dir` 给独立临时目录；`--virtual-time-budget` ≥12000；失败时去掉 `2>/dev/null` 看重试 stderr。
6. **Word/COM 中文路径崩溃**：若做 docx→pdf，把源复制到纯英文临时路径再转（当前流程纯 md→html→Edge 不涉及）。
7. **统计字符**：md 的字符数含标点与标题，达标判断按"全文字符总量 + 每节字数区间"双看。

## 小节结构模板（每小节固定 6 段）

1. **结论句开头**（1 句点破本节核心）
2. **痛点场景**（1-2 段真实尴尬/憋屈画面）
3. **底层逻辑拆解**（大白话讲透原理）
4. **方法/公式/步骤**（带引号话术模板或清单，单独成段，可直抄）
5. **场景演练**（1 个实例对话/演示）
6. **一句收束**（点题，简短有力）

## 配套资源

- `scripts/build_book.py` — 通用 md→HTML→PDF 构建器（CONFIG 含 title/kicker/toc_track/desc_lines/series_label/accent/card_gradient 等，命令行可覆盖 --series/--accent）
- `scripts/dupcheck.py` — **跨书重复度检测**（套话句池扫描）：按中文句末标点切句，统计同一句/同一句首出现在 ≥2 本书的次数，输出 `_dup_report.json`。批量出书必跑，字数达标不代表内容不雷同
- `scripts/gen_overview.py` — **合集总览页生成器**：从各书 `config.json` + `chapters/*.md` + PDF 字节级页数统计，生成 `20本合集总览.html`（含总字数/页数/话术数/禁用词命中、店铺分组、20 张卡片）。字数口径与 `qc.py` 对齐
- `scripts/build_book_multistyle.py` — **多风格封面版**构建器，支持 `gold_dark` / `vintage` / `minimal` / `book3d` 四种封面模板 + 同目录 `config.json` 覆盖配置。用于「复刻某对标账号店铺」这类需要一本书一种封面风格的场景（配合 `references/cover_styles.md`）
- `references/writing_guide.md` — 通用写作规范（复制到项目作 `WRITING_GUIDE.md`）
- `references/series_visual_guide.md` — 开窍系列封面结构/文案公式/主题配色表/序言结语骨架
- `references/cover_styles.md` — 4 种封面模板的视觉特征、元素落点、config schema 与实测坑位（折行/重复/贴顶等）
- `references/outline_generator.md` — 开窍系列章节结构规律 + 任意主题→OUTLINE 四步法 + 存量骨架 + 常见主题章名提案
- `references/batch_scaleup_and_qc.md` — **批量收口手册**（20 本 × 3 万字级批次验证过）：以磁盘为准的质检纪律、给每章「追加 X.7/X.8 小节」补厚的切片脚本、12 个禁用词的上下文清洗器（含全角引号与 `re.sub` 转义两个坑）、Edge 无头封面截图验证、合集总览页生成、并发写手撞车处置
- `references/en_edition_variant.md` — **英文版（美国版）变体做法**：本土化而非翻译的定位铁律、必换的美国平台/金融/法律语汇清单、`build_book.py` 英文变体的 7 处补丁（含模板识别字符 「→“ 这个致命项）、英文写作规范、中英质检口径差异

## 批量收口（多本一起交付前必做）

一本书写完后、整批交付前，按 `references/batch_scaleup_and_qc.md` 走一遍四件事：

1. **跑 `qc.py`（磁盘为准）** —— 绝不采信写手的"已完成"汇报，实测有 Agent 汇报 15 个文件实际只有 2 个。章节清单从每本 `config.json` 的 `toc_track` 动态推导，并核对 `toc_track` 与正文 H1 章名是否一致。
2. **补厚偏薄的书** —— 缺口 ≤40% 时给每章追加 X.7/X.8 小节（只写新增，保留原稿），比逐段改写省数倍工作量；各章小节数 6/7/8 混排可接受。
3. **禁用词全量清洗** —— 导出每处上下文再逐条替换，禁用词清单以写作规范为准（本系列 12 个，含「最后」）；**自己新写的内容也会带进禁用词，写完必须复扫**。
4. **重出 PDF + 视觉抽检 + 做合集总览页** —— 4 种风格各抽一本用 Edge `--headless=new` 截图核验封面；总览页的数量统计全部由脚本从磁盘实算，不手填。

## 并发铁律（实测踩坑）

**禁止同时派 8 个 background Agent 写书** —— 会撞平台频率限制（HTTP 429），全部任务一起挂掉，只落盘部分章节。安全做法：一次 2-4 路，或主 Agent 直接自己写。若已触发 429，兜底方案是主 Agent 逐章补齐（写作规范与大纲都已落盘，补齐不依赖 Agent）。
