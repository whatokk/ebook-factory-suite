# 批量补厚 + 禁用词清洗 + 磁盘为准质检（批次化生产经验）

> 来源于「复刻电子书20」（20 本 × 3 万字，总 68 万字）的收口阶段。适用于**任何批量出书**场景，尤其是用多 Agent 并行写长稿、最后要统一收口的时候。

## 一、磁盘为准质检（最重要的纪律）

**多 Agent 并行写书时，Agent 的完成汇报不可信。** 实测出现过：Agent 汇报「15 个文件已写、PDF 已生成」，磁盘上实际只有 2 个 md。

- 写一个 `qc.py` 放在书系根目录，只读磁盘，输出每本的：章节文件数 / 缺失章节 / 字数 / 「」话术数 / 禁用词命中 / PDF 是否存在及是否比最新章节旧。
- **章节清单要动态推导**：从每本 `config.json` 的 `toc_track`（用 `·` 分隔）推出应有的 9 个文件名，而不是硬编码一套骨架——不同店铺/系列的七章骨架往往不同（如"认知·模式·系统·产品·流量·人性·破局" vs "认知·心法·表达·谋略·兵法·修身·破局" vs "认知·生意·需求·执行·变现·经营·格局"）。
- **核对 `toc_track` 与正文 H1 章名是否一致**：不一致时以正文为准改 config（PDF 封面会用到 `toc_track`），否则封面目录与正文对不上。
- PDF 新旧判定：`os.path.getmtime(pdf) < max(os.path.getmtime(md))` 即视为「旧」，需重建。

## 二、跨书重复度检测（套话句池扫描）—— 批量出书必做

**字数达标 ≠ 内容不雷同。** 20 本由多路并行写手产出，最大隐患是跨书复用同一批开场/收束模板句。买家买两本就能对出来，这是零容忍项。

- **不要只看「篇内重复率」**：实测 20 本共 22,279 句，篇内去重率仅 0.30%（看着很干净），但跨书仍存在 **21 处模板句**。篇内指标会给出虚假安心。
- 扫描口径：按中文句末标点（`。！？!?`）切句 → 去掉 markdown 标记与分隔线 → 统计**同一句出现在 ≥2 本书**的次数。
- **句子长度门槛必须低**：`MIN=12` 会漏掉 7 字的「那么，从哪儿开始？」这类典型套话。**跑两轮：MIN=6 与 MIN=12**，低门槛那轮才是抓套话的关键。
- **必须过滤纯符号**：不过滤会在榜单里看到 `[7本 x7次] --` 这种由 `\n---\n` 分隔线拼出的假句。过滤条件是「句内必须含中文」`re.search(r'[\u4e00-\u9fff]', s)`。
- 另一路检测：**按句首前 10 字聚类**，找出「出现在 ≥4 本书的相同开头」（如「你身边一定有这样的人…」「读完这一章，你会知道…」）。这类句首模板即使整句不同，读感上也像同一套话。
- 已知可豁免项：**封面署名行**（如「——加微信xxx进读者群」）会出现在全部 20 本，属设计使然，不计入。
- 修复方式：**手术式等价替换**——只动那一条模板句，上下文一字不改，新句与本书书名/本章主题强相关，长度 ±10 字，且不得引入禁用词。
- 修复后必须 **重建受影响书的 PDF**（HTML 快照里仍留着旧句，PDF 不重建就等于没改），再复跑扫描确认归零。

脚本见 `scripts/dupcheck.py`。

## 三、补厚偏薄的书：给每章追加小节（比逐段改写省 4 倍工作量）

当一本书字数只有目标的 60%–90% 时，有两条路：

| 方案 | 工作量 | 适用 |
|---|---|---|
| 逐段扩写已有小节到 850-950 字 | 近乎重写全书 | 小节平均只有 300-400 字（缺口 >40%） |
| **给每章追加 X.7 / X.8 小节** | 只写新增部分 | 缺口 ≤40%，或想保留原稿不动 |

追加小节的落地套路（**不要用 Edit 逐段改，会被并发写手覆盖**）：

1. 把新小节按 `## X.Y 短标题｜副标题` 写成若干临时 md 文件（一个文件放 3-4 节，用 `---` 分隔）。
2. 用 Python 脚本切片并追加：

```python
import os, re, glob
blocks = []
for p in SRC_FILES:
    t = open(p, encoding='utf-8').read()
    for part in re.split(r'(?m)^## ', t)[1:]:          # 按 "## " 切小节
        part = re.sub(r'\n-{3,}\s*$', '', part.strip()).strip()   # 去掉尾部分隔线
        m = re.match(r'(\d)\.\d', part)                 # 章号取自 X.Y
        if m:
            blocks.append((int(m.group(1)), '## ' + part))
chaps = sorted(glob.glob(os.path.join(ROOT, 'chapters', '0[1-7]_*.md')))
for ch, block in blocks:
    path = chaps[ch - 1]                                # 章号 → 文件
    t = open(path, encoding='utf-8').read().rstrip()
    open(path, 'w', encoding='utf-8').write(t + '\n\n' + block + '\n')
```

3. 追加的小节同样要守六段式（结论句 → 痛点场景 → 底层逻辑 → 含「」的方法/清单 → 场景演练 → 一句收束），并**与本章已有小节不重复**。
4. 注意别追加到「收尾型」章节的末尾：若某章的第 7 节本身是结论式标题（如「留给十八岁的收尾一句话」），跳过该章更自然——**各章小节数不必强行统一**（6/7/8 混排是可接受的，20 本里就有多本如此）。

## 四、禁用词清洗器（含两个必踩的坑）

禁用词清单以写作规范为准（本系列 12 个：首先 / 其次 / 最后 / 综上所述 / 总而言之 / 不难发现 / 众所周知 / 相信通过 / 一方面 / 另一方面 / 值得注意的是 / 在这个时代）。

- **不要用一句正则全局替换**：这些词在叙事里是正常表达（"最后他说了一句…"），硬替换会毁掉文气。做法是**导出每处的上下文（前后 30-40 字）**，人工写一张 `(旧串, 新串)` 对照表，长串排前面（避免短串先吃掉长串）。
- **坑 1：引号字符不匹配**。正文用全角 `“”`，脚本里写 ASCII `'...'` 或 `"..."` 都匹配不上，会出现「替换了 13/19 处、还剩 6 处」的假成功。兜底用正则字符类：
  `Q = r'[\u201c\u201d\u2018\u2019"\'\u300c\u300d]'`，把引号位置写成 `Q`。
- **坑 2：`re.sub` 的替换串里含 `\u` 会报 `bad escape \u`**。用 `re.sub(pat, lambda m: new, t)` 传字面量，不要直接把含 `\u`/`\g` 的字符串当替换串。
- 自己新写的内容也会带进禁用词（实测我补的 16 节里带进 17 处「最后」）。**每次写完新内容必须复扫一遍**，把复扫当成写稿流程的一部分。
- 替换词库（按语义挑）：到头来 / 后来 / 收尾 / 末尾 / 临门一步 / 说到底 / 压轴一条 / 结果 / 然后。

## 五、封面视觉验证（Edge 无头截图）

```bash
EDGE="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
"$EDGE" --headless=new --disable-gpu --hide-scrollbars \
  --window-size=1240,1754 \
  --screenshot="D:\tmp\cover.png" \           # 输出必须用 Windows 反斜杠路径
  --user-data-dir="D:\tmp\edge_shot1" \       # 必须给独立 user-data-dir
  "file:///D:/.../书名.html"
```

- **必须用 `--headless=new`**：老的 `--headless` 在本机静默失败、不产出文件。
- 输出路径用 `D:\...` 反斜杠形式；用 `/tmp/...` 的 POSIX 路径会写不出来。
- 每个截图任务给一个**独立 `--user-data-dir`**，否则并行截图会互锁。
- 封面满版 A4：`.cover { page: cover; width:210mm; height:297mm }` 配 `@page cover { margin:0 }`，210mm ≈ 794 CSS px，据此可核对字号是否合适。

## 六、合集总览页（交付时顺手做）

批量交付 20 本 PDF 时，做一个 `20本合集总览.html` 比逐本解释有效得多：顶部放总本数/总字数/总页数/风格数/禁用词命中数（全部由脚本从磁盘实算，不手填），每个店铺一组统计胶囊，下面 20 张卡片链接到各自 PDF，卡内显示 NO.、封面风格、书名、副题、七章轨道、字数/页数/话术数。视觉沿用系列主色（本系列：米色底 `#f7f3e8` + 开窍金 `#c9a227` + 深色文字，无装饰 emoji）。

**两个易错点**：

1. **总览页必须用脚本生成，别手写**。首版是手写的，正文一改数字就全错，且没有生成器可复用。生成器落盘后，改稿 → 重跑 → 数字天然对齐。
2. **字数口径必须与 `qc.py` 一致**：`qc.py` 用的是 `len(re.sub(r'\s','',text))`（非空白字符数，含 markdown 符号），若总览页改用「纯中文汉字数」`[\u4e00-\u9fff]`，同一批稿子会算出 57.9 万 vs 68.1 万，差 10 万字，一眼就被当成数据错误。**任何统计口径先对齐既有质检脚本，再落新页面。**
3. PDF 页数在没有 pypdf/PyPDF2 的环境下，可用字节级统计兜底：`len(re.findall(rb'/Type\s*/Page(?![s])', open(pdf,'rb').read()))`——Edge 打印出的 PDF 对象头未压缩，此法准确（实测与设计值一致）。

## 七、并发写手的注意事项

- 子 Agent 并发上限实测 **2–4 路**安全，8 路必撞 429。
- 撞到 429 时，报错信息里通常提示"可切换其他模型"——`Agent` 工具显式传 `model: "reasoning"` 或 `"lite"` 常能绕过；若两个通道都 429，就改由主 Agent 自己写（主 Agent 不受该配额限制）。
- 同一个文件**绝不能有两个写手**：出现过两个 Agent 并发写同一本书、18 秒内互相覆盖的情况。发现撞车要立刻停掉一个，并明确移交归属。
